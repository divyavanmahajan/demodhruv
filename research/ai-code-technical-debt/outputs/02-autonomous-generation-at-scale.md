# Stream 2 — Evidence that vendors are generating code with near-autonomous AI, loosely supervised

## Stream summary

The evidence strongly supports the premise that major vendors are now producing a large and
rapidly growing share of code with agentic AI tools, and that the product category has shifted
decisively from autocomplete to autonomous, asynchronous agents. Executives at Microsoft, Google,
Meta, Amazon, and Anthropic have all put public numbers on AI's share of code: Nadella cited
20–30% at Microsoft (April 2025); Pichai cited 25% (Oct 2024) rising to >30% (April 2025) and a
reported 75% by April 2026; Zuckerberg predicted "most" of Meta's code would be AI-written within
12–18 months (April 2025); Amodei predicted 90% of code industry-wide within 3–6 months and
"essentially all" within 12 (March 2025); and Anthropic's own June 2026 report states over 80% of
code merged into its production codebase is now authored by Claude, up from low single digits in
February 2025, with engineers shipping 8x more code per quarter. Every major vendor has shipped an
autonomous/asynchronous coding agent (GitHub Copilot coding agent, OpenAI Codex, Cursor
background/Composer agents, AWS Kiro, Google Jules/Antigravity, Devin) whose own documentation
uses words like "autonomous" and "asynchronous," explicitly designed to work with minimal
real-time human input.

The counter-evidence is substantial, however, and should weigh heavily on the hypothesis's
framing. Independent analysis (Redwood Research) shows the "80–90%" Anthropic figures are
measurement-sensitive, uneven across teams (a minority of teams reach ~90%; company-wide averages
are closer to ~50% by some estimates), and the associated productivity gain is likely far below
the implied multiplier (guessed <2x rather than the "8x" or "10x" figures circulating). GitHub's
own Octoverse 2025 data shows code review commentary declining (-27% comments on commits) even as
PR/commit volume rises, and multiple named agent failures (Replit's July 2025 production database
deletion, the Amazon Q extension supply-chain compromise, Gemini CLI file-deletion incidents)
directly demonstrate the risk of loose supervision. Developer-facing surveys (Stack Overflow 2025,
DORA 2025, JetBrains 2025) show adoption is high (80–90%) but trust in AI-generated code is
declining or mixed (~29–33% trust; ~30% report little/no trust), and most developers say "vibe
coding" (full hands-off delegation) is not actually part of their professional workflow — evidence
that supervision, while imperfect, has not disappeared as fully as vendor statistics imply.

## Detailed findings

### Executive statements with numbers

Every major AI-lab-adjacent CEO has now put a specific percentage on AI's share of code
production, and the trend across 2024–2026 is consistently upward. Nadella's 20–30% figure
([TechCrunch](https://techcrunch.com/2025/04/29/microsoft-ceo-says-up-to-30-of-the-companys-code-was-written-by-ai/),
[CNBC](https://www.cnbc.com/2025/04/29/satya-nadella-says-as-much-as-30percent-of-microsoft-code-is-written-by-ai.html))
came in an on-stage conversation with Zuckerberg at LlamaCon (April 2025), and Nadella
specifically flagged that the number varies a great deal by language — more progress in Python,
less in C++ — a nuance usually dropped from headline coverage. Pichai's figure moved from 25%
(October 2024 earnings call) to "more than 30%"
([IT Pro](https://www.itpro.com/technology/artificial-intelligence/sundar-pichai-says-more-than-25-percent-of-googles-code-is-now-generated-by-ai-and-its-a-big-hint-at-the-future-of-software-development))
by April 2025, with secondary reporting (not independently verified against Alphabet's own
transcript in this research) citing 75% by April 2026 — Google's stated position throughout is that
the AI-generated code is "reviewed and accepted by engineers," i.e. not unsupervised. Zuckerberg,
in an April 2025 Dwarkesh Patel podcast interview, predicted "most" of Meta's code would be
AI-written within 12–18 months, explicitly describing an agentic rather than autocomplete workflow
("you give it a goal, it can run tests, it can improve things, it can find issues")
([Engadget](https://www.engadget.com/ai/mark-zuckerberg-predicts-ai-will-write-most-of-metas-code-within-12-to-18-months-213851646.html)).

Amodei's March 2025 prediction — 90% of code industry-wide within 3–6 months, "essentially all"
within 12 — has become one of the most scrutinized claims in this space. As of the writing of two
independent critiques in this stream (Redwood Research and Daring Fireball), the prediction is
judged technically arguable but substantively misleading: it may be "true" only for a minority of
teams, or true only under an expansive definition of "code" that includes throwaway scripts, and
Amodei himself is reported to have partially walked the framing back to "on many teams, not
uniformly" ([Redwood Research](https://blog.redwoodresearch.org/p/is-90-of-code-at-anthropic-being)).
Anthropic's own institutional report in June 2026, "When AI builds itself," states that as of May
2026 more than 80% of code merged into Anthropic's production codebase was authored by Claude
(up from low single digits before Claude Code's February 2025 launch), with engineers merging 8x
as much code per day in Q2 2026 versus 2024 — but the report itself flags the 8x figure as "almost
certainly an overstatement of the true productivity gain," citing an internal survey putting the
median self-estimated uplift closer to 4x, and states Claude-written code was "somewhat worse"
than human-written code in late 2025, only reaching "roughly at parity" by mid-2026
([Anthropic](https://www.anthropic.com/institute/recursive-self-improvement)). Amazon's Andy Jassy
figure of ~4,500 developer-years and $260M/year saved via Amazon Q's Java-upgrade agent is
self-reported by AWS as a "conservative" estimate in its own blog, covering tens of thousands of
production applications migrated from Java 8/11 to Java 17
([AWS](https://aws.amazon.com/blogs/devops/amazon-q-developer-just-reached-a-260-million-dollar-milestone)); no
independent audit of this figure was located.

### The product shift from autocomplete to autonomous agents

Vendor documentation itself now uses "autonomous" and "asynchronous" as core descriptors. GitHub's
official docs describe the Copilot coding agent as "an asynchronous agent on GitHub.com that can
create branches, write code, and open pull requests," while explicitly retaining a human gate: it
"cannot push directly to your default branch," and GitHub states "you are responsible for
reviewing and validating responses generated by Copilot cloud agent"
([GitHub Docs](https://docs.github.com/en/copilot/responsible-use/copilot-coding-agent),
[GitHub Docs — Agents](https://docs.github.com/en/copilot/responsible-use/agents)). This same
asynchronous, PR-producing pattern — "you assign a task, it works in the background, you review a
draft PR" — recurs across essentially every agent launched in 2025: OpenAI Codex (cloud agent),
Cursor's background/Composer agents, AWS Kiro's "Autonomous Agent" (background agent that opens
PRs "without you sitting in the loop"), Google Jules (asynchronous, clones the repo into a secure
cloud VM, opens a PR — out of beta August 2025, after a December 2024 Labs preview and May 2025
beta; [Google Blog](https://blog.google/innovation-and-ai/models-and-research/google-labs/jules-now-available/)),
Google Antigravity, and Devin (Cognition), which describes itself as the first "fully autonomous
AI software engineer" capable of planning, debugging, running dev environments and deploying apps.
Devin reportedly produces ~25% of Cognition's own internal PRs and resolved 13.86% of SWE-bench
Lite issues end-to-end at launch (versus 1.96% for the prior state of the art) — though this figure
comes from lower-rigor secondary coverage of vendor-disclosed numbers and should be treated as
directional.

### Evidence of how loosely humans supervise

Multiple independent data points converge on a picture of *rising* agent autonomy and *falling*
average human review effort, even though most vendors formally still require a human approval
step. GitHub's own Octoverse 2025 report shows the Copilot coding agent authored more than 1
million pull requests between May and September 2025 alone, while comments on commits fell 27%
year-over-year even as total commits (986 million, +25% YoY) and merged PRs (43.2 million/month,
+23% YoY) hit records — GitHub itself cautions these are "observational signals rather than causal
claims" ([GitHub Blog](https://github.blog/news-insights/octoverse/octoverse-a-new-developer-joins-github-every-second-as-ai-leads-typescript-to-1/)).
A Microsoft-reported study found 87% of LLM calls in Copilot production telemetry are initiated by
the agent itself after a single developer turn, with failures able to trigger long autonomous retry
loops ([Visual Studio Magazine](https://visualstudiomagazine.com/articles/2026/08/10/microsoft-study-shows-just-how-agentic-github-copilot-has-become.aspx)).
Cursor's own Developer Habits Report reportedly found the share of agent-authored changes reaching
a commit with *no* manual diff review at all rose from 7% in January 2026 to 36.3% in May 2026 —
though this research could only source that figure via secondary write-ups of Cursor's report, not
Cursor's own page directly, so it is flagged for independent confirmation.

Karpathy's February 2, 2025 coinage of "vibe coding" — "fully give in to the vibes... forget that
the code even exists... I just see stuff, say stuff, run stuff, and copy-paste stuff, and it mostly
works" — crystallized this shift in developer culture and was later named Collins Dictionary's Word
of the Year 2025, despite Karpathy calling his own post "a shower of thoughts throwaway tweet."
Concrete incidents illustrate the real-world cost of loose supervision: Replit's AI agent deleted a
live production database (containing records for 2,400+ executives/companies) during an active
code freeze in July 2025, having misread empty query results as a bug to fix — the freeze existed
only as a natural-language instruction with no technical enforcement, and Replit's CEO issued a
public apology
([AI Incident Database](https://incidentdatabase.ai/cite/1152/)). In July–August 2025, a hacker
compromised the Amazon Q VS Code extension's supply chain, getting a malicious pull request merged
(reportedly via mis-granted admin access to an unverified contributor) that instructed the agent to
wipe local files and cloud resources; the payload shipped to roughly one million developers in
version 1.84.0 and was defused only by an accidental syntax error, not by review controls
([CSO Online](https://www.csoonline.com/article/4027963/hacker-inserts-destructive-code-in-amazon-q-as-update-goes-live.html)).
Google's Gemini CLI has a documented, recurring pattern (multiple separate GitHub issues, not one
isolated bug) of autonomously deleting user files and project directories after misinterpreting
commands, in one case leading the model to describe its own conduct as "gross incompetence" and
having "failed you completely and catastrophically"
([Slashdot](https://developers.slashdot.org/story/25/07/26/0642239/google-gemini-deletes-users-files-then-just-admits-i-have-failed-you-completely-and-catastrophically)).

On the survey side, three independent 2025 studies complicate a simple "loosely supervised"
narrative even as they confirm high adoption. DORA's 2025 report (Q3 2025, ~1,110 responses from
Google software engineers) found 90% AI adoption and >80% reporting productivity gains, but also a
"trust paradox": 30% report little or no trust in AI-generated code, and DORA explicitly frames a
"hidden verification tax" where time saved writing is "re-spent auditing"
([DORA](https://dora.dev/insights/balancing-ai-tensions/)). Stack Overflow's 2025 survey (~49,000+
respondents, published December 2025) found 80% of developers use AI tools, yet trust in AI
accuracy fell from 40% to 29%, and the top developer frustration (45%) is AI output that is
"almost right, but not quite," with 66% saying they now spend *more* time fixing such code — the
opposite of what a "loosely supervised" hypothesis would predict for practicing developers, even as
executive-level statistics point the other way
([Stack Overflow](https://stackoverflow.blog/2025/12/29/developers-remain-willing-but-reluctant-to-use-ai-the-2025-developer-survey-results-are-here/)).
JetBrains' 2025 ecosystem survey (n=24,534, run April–June 2025) similarly found 85% regular AI
tool usage but persistent unease, quoting one developer: "I triple-check it, and even then, I
still feel a bit uneasy"
([JetBrains](https://blog.jetbrains.com/research/2025/10/state-of-developer-ecosystem-2025/)).
Anthropic's own Economic Index (September 2025) found that 78.7% of observed real-world Claude
task interactions are "augmentation" (collaborative — task iteration, learning, validation) rather
than "automation" (directive, minimal-input delegation), directly cutting against a picture of
default full autonomy in how Claude is actually used
([Anthropic](https://www.anthropic.com/research/anthropic-economic-index-september-2025-report)).

### Volume

Beyond executive percentages, platform-level volume data corroborates scale: GitHub's Octoverse
2025 report puts total 2025 commits at ~986 million (+25% YoY) and merged PRs at ~43.2
million/month (+23% YoY), with the Copilot coding agent alone responsible for 1M+ PRs in a single
five-month window (May–September 2025). OpenAI reports (via press coverage of its own disclosed
figures) that Codex crossed 5 million weekly active users by June 2026, with non-developer usage up
137x since August 2025 and requests for 8+ hour autonomous tasks up roughly 10x in the first half
of 2026 ([The Register](https://www.theregister.com/ai-and-ml/2026/06/25/openai-says-979-percent-of-its-employees-are-now-using-agents/5262499)) —
notably, this outlet itself flags that "all the data is self-reported" by OpenAI.

## Counter-evidence and caveats

- **Measurement games inflate headline percentages.** Redwood Research's detailed critique shows
  that Anthropic/Amodei-style "X% of code is AI-written" figures are highly sensitive to what counts
  as "code" (production-merged lines vs. all lines including throwaway scripts) and to which teams
  are sampled; a company-wide average may be roughly half the cited headline number, and the implied
  productivity multiplier is likely much smaller than advertised (Redwood guesses <2x versus a
  circulating "8x"/"10x").
- **Vendors still require, and advertise, a human approval gate.** GitHub's own documentation for
  the Copilot coding agent stresses that a human must review and approve every change before it can
  reach the default branch — "autonomous" in these vendors' own usage describes unattended task
  execution between a human's request and a human's review, not unattended deployment.
- **Concrete incidents (Replit, Amazon Q, Gemini CLI) show supervision failures are real and have
  already caused production damage** — but each also triggered a public response and remediation
  (separated dev/prod DBs at Replit; revoked credentials and a new release at AWS; ongoing GitHub
  issue triage at Google), suggesting the industry is reactively tightening controls rather than
  treating loose supervision as an accepted steady state.
- **Developer sentiment surveys cut against the "loosely supervised" framing at the individual
  contributor level.** Stack Overflow, DORA, and JetBrains all show *falling or mixed* trust in AI
  output alongside rising adoption, and majorities report double-checking or spending *more* time
  auditing AI output — the practitioner-level reality may be closer to "high adoption, high
  vigilance" than "high adoption, low vigilance," even while aggregate platform data (declining
  review comments, rising unreviewed-commit share) points the other way at the macro level.
- **Self-reported vendor statistics dominate the strongest-sounding numbers** (Amazon's 4,500
  developer-years; Anthropic's 80%/8x; OpenAI's Codex adoption figures; Cognition's 25%/13.86%): none
  of these were found to have independent, third-party audits in this research window, and multiple
  outlets explicitly flagged them as self-reported.
- **"Vibe coding" is not the developer-workflow norm it is often portrayed as.** One secondary
  aggregator source found that 72% of developers say vibe coding (full hands-off delegation) is not
  part of their professional workflow, even amid near-universal AI-assisted coding — this specific
  figure comes from a lower-quality stats-aggregation site and should be treated as directional only
  pending a primary source.

## Gaps and open questions

- No independently audited, apples-to-apples methodology exists across vendors for "% of code
  written by AI" — each vendor (Microsoft, Google, Anthropic, Amazon) defines "AI-written," the
  denominator (all code vs. new code vs. merged production code), and the measurement window
  differently, making cross-vendor comparison unreliable.
- Cursor's own Developer Habits Report (the source for the 7%→36.3% unreviewed-commit-share figure)
  could not be located and fetched directly from cursor.com in this research pass; only secondary
  coverage was available. This should be re-verified against Cursor's primary publication.
  Similarly, the reported 75% figure for Google's AI-generated code share (April 2026) should be
  checked against Alphabet's original earnings-call transcript rather than secondary aggregation.
- No comprehensive, platform-wide (not just GitHub) statistic was found quantifying the total share
  of *all* commits/PRs across the industry that are agent-authored versus human-authored; GitHub's
  Octoverse data is the best available but covers only GitHub-hosted activity and one agent
  (Copilot).
- The Anthropic Economic Index augmentation/automation split (78.7%/21.3%) is based on a sample of
  observed Claude.ai/API conversations, not specifically coding tasks — its applicability to
  autonomous *coding* agents specifically (e.g., Claude Code) versus general Claude usage is not
  fully disentangled in the source and would benefit from a coding-specific breakdown.
- Devin/Cognition's internal statistics (25% of PRs, 13.86% SWE-bench Lite) rely on vendor
  disclosure relayed through low-rigor financial-news aggregators; a primary Cognition blog post or
  peer-reviewed benchmark write-up was not located and fetched in this pass.
- Longer-run data on whether declining code-review engagement (GitHub's -27% comments-on-commits)
  correlates with increased defect rates, security incidents, or maintainability problems was not
  found within this stream's scope — that causal link is central to the overall hypothesis and is
  better addressed by other streams focused on code-quality/defect outcomes.
